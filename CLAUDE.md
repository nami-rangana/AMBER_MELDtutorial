# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A tutorial/working directory for running **MELD** (Modeling Employing Limited Data) restrained
replica-exchange molecular dynamics (REMD) folding simulations using **AMBER** (sander/pmemd) on the
UF HiPerGator HPC cluster. It is not a software library — there is no build/lint/test suite. "Running
the code" means executing tleap/sander/pmemd binaries and small Python helper scripts, usually via SLURM
batch jobs. The full walkthrough with rationale for each step lives in [README.md](README.md); read it
before making changes to the pipeline scripts, since the numbered directories mirror its sections exactly.

## Pipeline architecture

The repo is organized as a linear, numbered pipeline. Each stage's outputs feed the next stage as inputs,
and the directory names correspond 1:1 to README sections:

1. **`1_system_setup/`** — Build the system from a FASTA sequence using `tleap` (ff19SB force field,
   `mbondi2` PB radii for GB, `igb=5`). [makeLeap.x](1_system_setup/makeLeap.x) converts the FASTA to a
   3-letter-code `leap.in` script, which produces `1uoa.prmtop`/`1uoa.inpcrd`. Then `sander` minimizes the
   structure (`min.in` → `min.rst`).
2. **`Helpers/`** — Cross-cutting utilities used before/between stages, not tied to one pipeline step:
   - [temperature_scale.py](Helpers/temperature_scale.py): generates the replica temperature ladder
     (`constant`/`linear`/`geometric` scaling) → `temperatures.dat`, one temperature per line, consumed by
     every later stage's `gen_*_inputs.py`.
   - [gen_restraints_prot.py](Helpers/gen_restraints_prot.py): reads the topology (prmtop), FASTA sequence,
     and a secondary-structure string file (`ss.dat`, one line of H/E/. per residue) to auto-generate MELD
     restraints — beta-sheet (SS) distance restraints, helix (phi/psi torsion + CA-CA distance) restraints,
     and hydrophobic-contact (HP) distance restraints. Emits an AMBER `&rst`-format restraint file
     (`restraints.rst`) plus a MELD `restraints_index.txt` describing collections/groups/active-fractions
     (format documented in detail in the README's "Restraints" section — collection count, groups-per-collection,
     active-restraints-per-group, and active-percentage-per-collection are all order-sensitive header lines).
3. **`2_equilibration/`** — Per-replica pre-equilibration at each replica's target temperature (no exchange
   attempts yet), using [gen_eq_inputs.py](2_equilibration/gen_eq_inputs.py) to stamp a template
   `equilibrate.mdin` (placeholders `XXXXX`=temperature, `RANDOM_NUMBER`=random seed) into one `.mdin.NNN`
   file per replica plus an `equilibrate.groupfile` for `sander.MPI -ng N -groupfile`. MELD restraints are
   read here too (`nmropt=1, meld=1, indxf='restraints_index.txt'`, `DISANG=restraints.rst`) but with a
   ramped-down restraint weight (`&wt type='REST'`) since the starting structure is unfolded.
4. **`3_meld_remd/`** — Production replica-exchange run. [gen_md_inputs.py](3_meld_remd/gen_md_inputs.py)
   is the REMD analogue of the equilibration generator (`-rem 1 -remlog rem.log`, restart path pattern with
   `{rep}` placeholder), producing `remd.groupfile` for `pmemd.cuda.MPI -ng N -groupfile` (GPU-accelerated,
   unlike the CPU-only equilibration step).
5. **`HiperGator/`** — Cluster-specific instructions ([INSTALL_GUIDE.md](HiperGator/INSTALL_GUIDE.md)) for
   building AmberTools25 + pmemd24 (with the MELD patch) from source via cmake on HiPerGator, and a sample
   [run_cmake](HiperGator/run_cmake) invocation. Not part of the simulation pipeline itself.
6. **`gpu_eq/`** and **`nomeld/`** — Alternate/exploratory equilibration setups kept alongside the main
   pipeline: `gpu_eq/` mirrors `2_equilibration/` but targets GPU equilibration, and `nomeld/` is a
   parallel run against a *different* test protein (`3gb1.prmtop`, GB1) without MELD restraints, used as a
   comparison/control. These are not later pipeline stages — don't treat them as continuations of
   `1_system_setup` → `2_equilibration` → `3_meld_remd`.

Top-level `*.sh` files (`imesh.sh`, `terminal.sh`) are one-off SLURM job scripts for specific runs on
HiPerGator (`hpg-turin` partition, `alberto.perezant` account/qos), not general-purpose entry points.

## Working in this repo

- Most directories are full of **simulation output artifacts** committed alongside scripts: `.mdout`,
  `.mdcrd`, `.mdinfo`, `.rst`, `logfile.NNN`, `meld.info.worldrank*`, `.err`/`.log`. These are generated by
  running the pipeline, not hand-written — don't try to "fix" or refactor them, and don't assume they
  reflect the current state of the template/generator scripts (they may be stale from a previous run).
- Per-replica files are numbered `NNN` (e.g. `equilibrate.mdin.001`…`.030`) and are all produced by the
  same `gen_*_inputs.py` script from one template — when changing replica behavior, edit the template
  (`equilibrate.mdin` / the `remd.mdin` template) or the generator script, not individual numbered files.
- The number of replicas is driven entirely by how many lines are in `temperatures.dat`; there's no
  separate "replica count" config to keep in sync.
- Running any stage requires an AMBER environment sourced first (`source <amber_path>/amber.sh`, or on
  HiPerGator the project's install at `/orange/alberto.perezant/t.desilva/amber_setup/pmemd24/amber.sh`)
  plus `ml gcc/14.2.0 openmpi/5.0.7` (and `cuda/12.8.1` for GPU/pmemd.cuda steps).
